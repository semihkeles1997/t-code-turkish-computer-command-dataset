# T-Code v4 Dataset Card

T-Code v4 is a Turkish computer-control command resource designed for token-level decomposition of compound commands into ordered executable subtasks.

## Composition

- Final resource: 2,700 records
- Domains: 4 balanced domains, 675 records each
- Task-token labels: 33 classes including `O`
- Boundary labels: 3 (`B-TASK`, `I-TASK`, `O`)
- Main data format: JSONL

## Domains

- `temel_bilgisayar`
- `tarayıcı_internet`
- `ofis_metin_düzenleme`
- `dosya_yazılım_geliştirme`

## Record fields

The final JSONL records provide the command text and aligned annotation layers used by the benchmark, including task segments, task labels, tokens, boundary labels, and task-token labels. Raw and normalized command forms are retained where available.

## Provenance and scope

The resource consists of designed textual examples rather than logs collected from deployed users. The `source_type` field records construction categories used during dataset development. These categories describe the composition of this resource and should not be interpreted as estimates of how frequently real users issue particular types of commands.

The benchmark does not contain automatic-speech-recognition noise generated by a live ASR system, application-state traces, execution-success records, or real user identity records.

## Challenge material

The 100-command challenge set was prepared separately from the 2,500-record main resource to provide a more difficult wording-shift evaluation containing phenomena such as corrections, fillers, negations, and context-sensitive expressions.

A 99-command variant excludes one near-duplicate identified during pre-augmentation review. This filename intentionally says `excluding_identified_neardup` rather than `no_neardup`: the later 200-record augmentation stage was informed by challenge-set error patterns, so the 99-command variant should not be interpreted as a fully decontaminated external test relative to the final augmented training data.

## Intended use

The resource is intended for research on command decomposition, sequence labelling, annotation analysis, and comparable benchmark evaluation. The fixed internal test and challenge material should remain outside training and future data augmentation when used for benchmark comparisons.

## Non-use and limitations

T-Code does not establish the safety or usability of an end-to-end computer-control system. Predictions should not themselves authorize destructive or consequential actions such as deleting, sending, moving, or renaming user data. Downstream systems require independent safeguards.

The repository also does not provide a byte-for-byte reconstruction of every historical model-training environment; some low-level optimization settings from the original runs were not retained consistently.
